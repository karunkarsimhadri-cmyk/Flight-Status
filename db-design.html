📐 Merge Logic (DB level)

  • Both provider responses stored in provider_responses
  • Merge rule: pick row with later last_updated_utc
  • Merged result written to flight_statuses
  • source_provider_id records which provider won the merge

📊 Status Normalisation

  • raw_status keeps provider's own vocabulary
  • unified_status is computed: compare actual vs scheduled times
  • ≤ 15 min diff → OnTime; > 15 min → Delayed
  • Provider-specific cancelled/diverted keywords → mapped enum

🔐 Indexes

  • flights: UNIQUE (flight_number)
  • provider_responses: (provider_id, flight_number, flight_date)
  • flight_statuses: UNIQUE (flight_number, flight_date)
  • status_lookup_log: (flight_number, flight_date, requested_at)

🏗 AeroTrack vs QuickFlight

  • AeroTrack → terminal, gate, delay_reason populated
  • QuickFlight → those fields are NULL in provider_responses
  • flight_statuses inherits NULLs if QuickFlight is preferred source
  • Frontend hides fields when NULL (AeroTrack Details card)
